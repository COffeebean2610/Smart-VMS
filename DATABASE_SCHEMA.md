# Database Schema

The system uses MongoDB (NoSQL). Below are the primary collections and their document structures.

## 1. `cameras` Collection
Stores registered camera endpoints.

```json
{
  "_id": "ObjectId",
  "cameraName": "String (e.g., Main Entrance)",
  "type": "String (e.g., webcam, ip, rtsp)",
  "url": "String (e.g., 0, http://192.168.1.100/video, rtsp://...)",
  "status": "String (online, offline)",
  "createdAt": "ISODate",
  "updatedAt": "ISODate"
}
```

## 2. `rois` (Region of Interest) Collection
Stores user-drawn polygons for detection zones.

```json
{
  "_id": "ObjectId",
  "zoneName": "String",
  "cameraId": "String (Reference to cameras._id)",
  "coordinates": [
    {
      "x": "Float (Normalized 0.0 to 1.0)",
      "y": "Float (Normalized 0.0 to 1.0)"
    }
  ],
  "createdAt": "ISODate"
}
```

## 3. `events` Collection
Logs intrusion detections generated by the YOLO engine.

```json
{
  "_id": "ObjectId",
  "eventType": "String (e.g., Intrusion, Person Detected)",
  "cameraId": "String",
  "roiName": "String",
  "confidence": "Float (e.g., 0.85)",
  "timestamp": "ISODate",
  "snapshot": "String (Relative path: /storage/snapshots/123.jpg)",
  "recordingId": "String (Reference to recordings._id)",
  "videoTimestamp": "Float (Seconds offset in the recording when this happened)",
  "status": "String (active, resolved)"
}
```

## 4. `recordings` Collection
Logs finalized continuous video recording segments.

```json
{
  "_id": "ObjectId",
  "cameraId": "String",
  "startTime": "ISODate",
  "endTime": "ISODate",
  "duration": "Float (Seconds)",
  "filePath": "String (Absolute or relative path to .mp4)",
  "fileSize": "Integer (Bytes)",
  "status": "String (completed)"
}
```
